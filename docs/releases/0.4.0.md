# Chaos HDR 0.4.0 — experimental source release

This release adds the Chaos HDR sidebar, independent HDR and sharpening,
and safer updates and GPU-resource cleanup. Version 0.3.0 was an unpublished
development candidate; these changes ship as 0.4.0.

The installer contains reviewed source and builds locally. Fresh-system
installation, startup after a new login and a full upgrade from the hosted
release remain unverified. Existing-system and isolated tests are not a
substitute for those acceptance checks.

## Changes

- Translucent, full-height Chaos HDR sidebar with neon branding, animated
  lightning and smooth reversible Alt+Z transitions.
- Independent HDR and sharpening, compact controls and hover descriptions.
- Regional input handling, visible cursor and KDE screenshot selection support.
- Optional reduced motion, native accessible controls, clipboard editing and
  installed-font fallback for Unicode profile names and application titles.
- One effective display peak for the UI, NVIDIA engine and output metadata;
  follows the selected window between displays and bypasses HDR on SDR outputs.
- In-memory render settings, debounced persistence and interrupted-save recovery.
- Conservative transparency bypass, bounded processing retries, screen-removal
  cleanup, bounded overlay resources and no unused direct-path capture texture.
- Immutable builds, complete asset fingerprints, staged release activation,
  rollback records, installed-version reporting and interrupted-update recovery.
- Portable source checks and an opt-in, dedicated-runner graphics workflow.
- Completion-gated GPU cleanup, retained in-flight buffers and bounded recovery;
  unresolved GPU resources disable processing until a new compositor session.

## Validation

The implementation passed 47 Python tests, native settings and motion checks,
and isolated KDE tests for input, screenshot selection, pixel output, multiple
displays, failed-update rollback and processing retries. Four simulated GPU
completion-failure scenarios passed with Vulkan validation enabled. These tests
use synthetic windows and do not launch a game or induce a real GPU hang.

Matched local GPU-processing medians with HDR and sharpening enabled and the
sidebar closed were 0.271 → 0.269 ms at 1440p and 0.492 → 0.490 ms at 4K.
With the sidebar open, they were 0.277 → 0.275 ms and 0.490 → 0.490 ms,
respectively. These are processing measurements on the test system, not an
input-to-display latency guarantee. Ordinary toggles showed no measured
regression; forced cold resource recreation was about 26–28 ms slower at the
median because cleanup now confirms completion before replacing resources.

The graphics workflow requires a dedicated supported NVIDIA/KDE Wayland runner,
matching KWin headers, the pinned runtime in `.venv`, and the pinned SDK. It is
manual, restricted to the main branch and uses the `graphics-validation`
environment. Configure required reviewer protection on that environment before
enabling it. No game is launched and no private captures are uploaded.

A true GPU hang is not induced on the user's working desktop. The direct path
avoids queuing an unfinished producer and avoids CPU waits for its preceding
submission. Cleanup polls completion instead of explicitly waiting for device
idle, and retains unresolved resources to prevent use-after-free. Software fault
checks do not prove recovery from a real driver hang. Device-loss testing on a
disposable system with a separate GPU remains required for that claim.

## Distribution boundary

Only the allowlisted source installer, source archive and checksums are suitable
release artifacts. Original code remains GPL-2.0-only; upstream licenses remain
separate. Fonts/artwork provenance is retained. The combined KWin/NGX binary
redistribution question is unresolved, so compiled binaries and dependencies
must not be included. Do not replace a published asset with a different build.
