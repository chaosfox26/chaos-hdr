# Chaos HDR 0.2.0 — KWin 6.8.1 compatibility

Prepared release notes for the experimental 0.2.0 source update. The implementation
is merged; release verification and separate authorization to tag or publish are
still required. This document does not publish the release.

## Restores compatibility after the KWin update

Rebuilds the native effect for KWin 6.8.1 following the 6.8.0-to-6.8.1 update.
The previous installation correctly refused to load a mismatched native effect,
which also prevented Alt+Z from drawing its controls even though the services and
shortcut were running. The compatibility guard remains in place. Startup errors
now report the mismatched versions and recovery step in the user service journal.

## Updates and recovery

- Alt+Z includes Updates & repair. The launcher and Alt+Z shortcut also open a
  recovery window if the native HDR effect cannot load.
- Automatic checks query this project's GitHub releases at most once every
  24 hours, including failed attempts and across login restarts. Manual checks
  are available separately. No commit or branch is treated as a published release.
- A newer applicable release produces “Chaos HDR has an update” and appears in
  the controls. Stable installations exclude prereleases; this experimental
  installation includes them. Checks show last-attempt and offline/error status.
- Install downloads and verifies the release installer using GitHub's SHA-256
  asset digest. Packaged installs preserve profiles and app approvals and retain
  a source backup. Source checkouts require a clean tree and an official origin,
  and only fast-forward to a newer release without discarding local commits.
- Rebuild for this desktop runs existing setup without requiring a new release.
  Only Chaos HDR's services restart. A separate setup unit survives those restarts.
  If running and installed KWin differ, sign out/in before rebuilding.

No updates install automatically. Setup may request system authentication for
missing prerequisites. It does not restart the desktop or reboot the computer.
Future KWin API changes may still require source changes and a new release; a
rebuild is not a promise of universal future compatibility. HDR conversion,
debanding and sharpening algorithms are unchanged.

## Validation and remaining acceptance work

- 31 local automated tests passed for version guards, release ordering/channels,
  daily throttling, errors, digest checks, source protection, settings preservation
  and cleanup. These are local fixture results, not GitHub CI results.
- An existing-machine production rebuild/install and the independent rebuild
  service completed on KWin 6.8.1. The effect loaded, health/readiness checks and
  Alt+Z passed, and saved settings retained their hashes. No new login, desktop
  restart, reboot or real-application conversion test was performed.
- Recovery UI testing used an isolated session bus and offscreen rendering.
  Installer integrity/extraction and settings preservation used local checks;
  uninstall checks used isolated fixtures. They do not establish fresh-system
  installation or end-to-end recovery on another supported machine.
- Installation from a genuinely newer hosted release remains fixture-tested.
  No fabricated release was published for testing.

The actual published one-command installation still needs a fresh supported-system
test covering dependency downloads, the full production build, services and Alt+Z,
real TrueHDR conversion of an explicitly approved compatible SDR window, controls,
saved profiles, startup after a new login and uninstall with settings preservation.
Until those results are recorded, the public workflow is not fully validated.

and verify the public allowlisted source installer after review, with versioned
