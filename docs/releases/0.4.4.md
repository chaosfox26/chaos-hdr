# Chaos HDR 0.4.4 — fresh HDR frames

**[Download Chaos-HDR-CachyOS.run](https://github.com/chaosfox26/chaos-hdr/releases/download/v0.4.4/Chaos-HDR-CachyOS.run)**

Install the latest regular release with the permanent command:

```sh
curl -fsSL https://github.com/chaosfox26/chaos-hdr/releases/latest/download/install.sh | bash
```

The launcher pins this release's installer and verifies its SHA-256 before setup.
Existing picture profiles, allowed applications and launch settings are preserved.

## What changed

Version 0.4.3 could deliberately redraw an older HDR output while its previous
job was still busy. That avoided repeated SDR/HDR brightness changes but could
produce visible repeated images under load. Version 0.4.4 removes that reuse
branch: each successful processing draw converts its submitted input.

The route keeps one conversion job and one output image. It first checks whether
the prior HDR job has completed and waits on its fence for up to 100 ms only if
still busy. A timeout pauses processing until an explicit retry. This bounded
CPU wait can delay the compositor; it is not a zero-wait or asynchronous design.
The producer fence remains an existing GPU semaphore dependency, without a
duplicate CPU producer-readiness poll. Direct output ownership is released after
each draw. No extra frame queue, image copy, blending or HDR pass is added.

Startup, unsupported input and paused/error states can use the ordinary window
path. A readiness timeout does not repeatedly switch between SDR and HDR each
frame. The correction does not guarantee delivery of every game frame or zero
latency. The neon sidebar, separate controls, font correction and completion-gated
GPU retirement remain in place. KWin retains presentation and VRR policy control.

## Gameplay measurements

The following numeric samples were collected on an existing CachyOS KDE Plasma
Wayland installation with KWin 6.8.2. Temporary measurement code used the same
processing and synchronization sources as the production build. It recorded
numbers only and was removed afterward. These are observations of two different
gameplay workloads, not a controlled comparison between the two games.

| Measure | 30-minute gameplay, HDR on/sidebar closed | 3-minute high-load gameplay |
|---|---:|---:|
| Analyzed GPU processing samples | 178,702 | 75,315 |
| GPU preparation + processing median | 0.2713 ms | 0.2710 ms |
| GPU preparation + processing p99 | 0.2756 ms | 0.2772 ms |
| GPU preparation + processing maximum | 0.2868 ms | 0.2854 ms |
| CPU draw span median / p99 | 0.1054 / 0.2583 ms | 0.0999 / 0.1717 ms |
| Explicit prior-job CPU wait median / maximum | 0.00093 / 2.25690 ms | 0.00085 / 0.05483 ms |
| Longest observed compositor interval | 685.833 ms | 16.671 ms |
| Observed intervals over 25 ms | 722 | 0 |

The short high-load run averaged about 98% whole-GPU utilization and recorded
no HDR-state change, processing error or recovery-required state. The normal
effect and all checked settings were restored/verified afterward. Visual motion
reports were improved in the tested sessions; no universal ghosting guarantee is
claimed. These timing traces alone do not prove converted-image freshness.

The longer run included substantial gaps between game updates. For its largest
presentation gap, about 684 of 686 ms already existed between KWin-observed
update receipts; nearby HDR GPU work remained near 0.27 ms. These observations
do not attribute the gaps to HDR conversion. They also do not establish the
precise cause: game/driver work, shader compilation, asset loading and delayed
compositor event handling were not distinguished. Cache writes are not proof of
a shader-caused hitch. Broader game/Proton input-stall diagnosis is separate from
this frame-handling release.

Measurements exclude warmup rows and gaps between bounded trace windows. They
are not uninterrupted every-frame coverage. GPU values describe the previously
completed job. Compositor feedback is not game-engine FPS, does not identify
frame generation and is not input-to-display latency. CPU and GPU spans overlap
and must not be added as a total latency figure. Instrumentation overhead was
not independently established, and there is no matched long HDR-off baseline.

The historical 1440p and 4K values remain documented in the [README](../../README.md)
and [0.4.3 notes](0.4.3.md); they are not fresh 0.4.4 measurements at both resolutions.
See [performance guidance](../performance.md) for measurement scope.

## Release contents and support

Public assets contain the reviewed production source installer, matching source
archive, pinned one-command launcher and checksums. They exclude personal
settings, game records, captures, temporary timing builds, gameplay loggers,
monitoring services, traces, private audit reports, compiled binaries and
installed dependencies. Production diagnostics remain disabled by default.
Dependencies are downloaded from their publishers and built locally.

Tested environment: **an existing CachyOS installation with KDE Plasma Wayland**.
Other distributions and desktops, including GNOME, remain untested. The effect
requires KDE/KWin, a compatible NVIDIA RTX GPU/driver and KDE HDR enabled.
Fresh-system installation and startup after a new login remain unverified.
This is an experimental source release; the combined KWin/NGX binary licensing
question remains unresolved. See [installation](../installation.md) and
[third-party notices](../../THIRD_PARTY_NOTICES.rst).
