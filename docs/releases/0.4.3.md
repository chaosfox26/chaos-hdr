# Chaos HDR 0.4.3 — stable HDR frame handling

**[Download Chaos-HDR-CachyOS.run](https://github.com/chaosfox26/chaos-hdr/releases/download/v0.4.3/Chaos-HDR-CachyOS.run)**

Install the latest regular release with the permanent command:

```sh
curl -fsSL https://github.com/chaosfox26/chaos-hdr/releases/latest/download/install.sh | bash
```

The command follows future regular releases. This release's launcher pins its
own 0.4.3 installer and checks its SHA-256 before running setup.

## What changed

A temporary readiness gap could draw the original SDR game image instead of
the converted HDR output, causing repeated brightness changes even with the
sidebar closed. The effect now retains its last valid HDR output during a
pending conversion, with the output's actual color interpretation preserved.
OpenGL releases that image after its final read and before the next conversion.

The duplicate CPU poll of the producer fence has been removed. The existing
imported GPU semaphore already prevents processing before the producer finishes.
Command resources and input-buffer cache entries are reused only after the
preceding HDR job completes. The queue watchdog and completion-gated cleanup
remain in place.

There is no additional HDR job, output buffer, image copy, blending pass or
frame-pacing timer. A genuinely unfinished HDR job can still repeat the last
image; this can delay visible new content and is not a zero-latency guarantee.
Unsupported input and initial startup before any valid result retain the normal
window path. The design continues to process submitted buffers inside KWin,
without injecting into the game.

KWin retains control of VRR and presentation. Actual presentation feedback
reported Adaptive Sync with HDR enabled and disabled in the tested setup;
no global VRR override was needed. Development feedback now includes the
presentation mode. Normal production has timing diagnostics disabled.

The neon sidebar, independent picture controls and 0.4.2 font fix are preserved.

## Local validation and timing

| Check | Existing flicker correction | 0.4.3 producer synchronization |
|---|---:|---:|
| Live 2560 × 1440 GPU median | 0.268832 ms | 0.268800 ms |
| Live 2560 × 1440 GPU p99 | 0.271776 ms | 0.271584 ms |
| Live completed conversion samples | 1,970 | 1,980 |
| Older HDR output reused in those samples | 0 | 0 |
| Synthetic 3840 × 2160 GPU median | 0.446560 ms | 0.444512 ms |
| Synthetic 3840 × 2160 GPU p99 | 0.451392 ms | 0.448384 ms |

The 1440p comparison used baseline/candidate/candidate/baseline four-second
samples, HDR with sharpening at 40%, and a closed sidebar. Sharpening-only
processing measured 0.022240 ms median in a separate four-second sample.
The 4K comparison used a moving synthetic fixture, sharpening at 50%, a closed
sidebar and Vulkan validation on a virtual VSync output. Resolution order was
reversed between baseline and candidate. These conditions differ from the
[historical 0.4.0 benchmark](0.4.0.md).

These are local GPU preparation-plus-processing measurements, not physical
input-to-display latency or a universal performance promise. The comparisons
support no material regression, rather than a measurable speedup. No repeated
output in a short sample does not rule out repeats under greater GPU load.
Current-commit presentation feedback also does not establish cached-image age.

Isolated KDE checks passed for controls, independent toggles, synthetic
sharpening reference pixels, healthy unload/reload, temporary and persistent
completion failures, post-submit failure, simulated device failure, unexpected
unload and quiet-frame recovery. Vulkan validation reported no errors. Software
fault injection does not reproduce a physical GPU or driver hang.

## Release files and support

- `Chaos-HDR-CachyOS.run`: self-extracting source installer.
- `Chaos-HDR-CachyOS-source.tar.gz`: matching reviewed source.
- `install.sh`: downloads, verifies and runs this release's installer.
- `SHA256SUMS`: checksums for those three files.

Existing profiles and app approvals are preserved. Public packages exclude
personal settings, captures, diagnostic traces, installed dependencies and
compiled binaries. Dependencies are downloaded upstream and built locally.
Previously reviewed images and third-party licensing boundaries are unchanged.

**Tested desktop: an existing CachyOS installation with KDE Plasma Wayland.
Other distributions and desktops, including GNOME, remain untested for
installation and runtime use.** The effect requires KDE/KWin, a compatible
NVIDIA RTX GPU/driver and HDR enabled in KDE. Fresh-system installation and
startup after a new login remain unverified. This is an experimental source
release; see [installation](../installation.md) and [notices](../../THIRD_PARTY_NOTICES.rst).
